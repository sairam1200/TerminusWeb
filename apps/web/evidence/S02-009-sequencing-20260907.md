# S02-009 terminal sequencing and rejected-session recovery

Owner: Session 02. Queue authorization: `e32d17b`. Existing web source was
equivalent to integration baseline `b7eef26`. No protocol contract changes.

## Confirmed defect

Before changing the adapter, the new regression was run with:

`npx vitest run terminal/protocolTerminalAdapter.test.ts -t 'assigns distinct ordered sequences'`

It failed: concurrent resize/input/resize emitted sequence numbers `[3,3,3]`
instead of `[3,4,5]`. Sequence allocation occurred before asynchronous contract
validation committed the counter. This is a socket-double reproduction, not an
iPhone or production connection test.

## Changes

- Serialize outgoing allocation, validation, send and rollback with incoming
  contract application. Release the lock before receive side effects so ping/pong
  cannot deadlock. A failed send cannot roll back concurrent incoming progress.
- Reserve queued bytes together with existing socket buffering against the
  existing 64 KiB bound. A maximum safe integer sequence placeholder makes this
  reservation deliberately conservative near the limit. Snapshot queued payloads
  so caller mutation cannot change a validated reservation.
- Fence socket callbacks, asynchronous authentication, queued sends and their
  continuations by connection generation. Order terminal credential persistence
  and subsequent loads across replacement adapters, preventing a delayed old
  save from overwriting newer pairing state.
- Give a rejected reopen explicit bilingual guidance and New Session recovery.
  Stop automatic foreground retries of that rejected locator. Keep the existing
  URL locator until the user chooses recovery and a new session actually opens;
  do not silently discard or close a live session.
